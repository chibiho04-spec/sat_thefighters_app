# メディア（カード）使用記録 設計書

作成日: 2026-09-28
対象: `index.html`（案件管理アプリ本体）

## 目的

LINE の「Sat メディア管理 Bot」でやっている記録（撮影で持ち出した CFexpress カードの記録）を、
アプリの中で完結させる。**記入はワークシートで**、**一覧・カードの現在地は管理室のメディア管理で**見る。
bot は卒業する（本人決定 2026-09-28）。

bot の8問（そのまま項目にする）:

| # | bot の質問 | 入力 |
|---|---|---|
| 1 | 使用日 | 日付（複数可） |
| 2 | 持ち出したメディア | カードの複数選択 |
| 3 | 使用したメディア | カードの複数選択 |
| 4 | 現場名 | 自由入力 |
| 5 | バックアップは完了しているか | ○／未 |
| 6 | 使用者 | 名前 |
| 7 | バックアップした人 | 名前 |
| 8 | 返却者 | 名前 |

## 決定事項（本人）

- 記録の入口は**ワークシート**（通常＋簡易）。単独の「新規メディア記録」画面と「＋」ボタンは**廃止**
- 作業後記入の「💾 メディア使用記録」テキスト欄は**削除**。新しい「💾 メディア」欄を**私物機材の上**に置く
- 機材リスト（チェックリスト）から「💾 メディア」カテゴリを**外す**（機材マスタには残す）
- ワークシート印刷には**「持ち出し」の1行だけ**入れる
- カードの一覧はアプリ内で編集でき、全端末で共有する
- 初期カード: CFexpress Type A 160GB ×4（`CF160_1`〜`CF160_4`）、256GB ×2（`CF256_1`〜`CF256_2`）
- bot の過去記録は CSV から1回取り込み、一覧に「LINE」の印付きで並べる（閲覧のみ）

## 触らないもの

売上・請求書・同期の仕組み（GAS）・スタッフデータ。GAS の再デプロイは不要。

## 1. データ

### 1-1. ワークシート本体に `media` を1つ足す

通常ワークシート `ws_${num}` と簡易ワークシート（`simple_ws` の各レコード）に、同じ形の `media` を持たせる。
どちらも既存の同期（`order` kind ／ `simpleWS` kind）に**そのまま乗る**ので、新しいシートは要らない。

```js
media: {
  date:     '2026/08/17',          // 使用日。空ならワークシートの日程（簡易は日付）を使う
  out:      ['CF160_1','CF160_2'], // 持ち出したカード（カードID）
  used:     ['CF160_1'],           // 使用したカード
  user:     '城間',                // 使用者
  bu:       true,                  // バックアップ完了
  buBy:     '平岡',                // バックアップした人
  returnBy: '城間',                // 返却者。空＝返却未
  memo:     ''                     // 備考（旧「メディア使用記録」の文はここへ引き継ぐ）
}
```

- 現場名は持たない。通常WSは件名、簡易WSは件名（無ければ内容）を使う
- `media` が無い／`out` と `used` が両方空 ＝「記録なし」。一覧には出さない
- 旧テキスト欄 `wsd-media` の値は、開いたときに `media.memo` が空なら備考欄へ表示し、保存時に `media.memo` に入れて `wsd-media` は空にする（二重に残さない）

### 1-2. カードの一覧（全端末共有）

`config` kind に **キー `mediaCards`** を1件追加（受注分類 `orderTypes` と同じ仕組み）。

```js
{ 'キー': 'mediaCards', list: [
  { id: 'CF160_1', type: 'CFexpress Type A 160GB', retired: false },
  ...
], _updatedAt: '...' }
```

- `id` が画面に出る名前そのもの（bot と同じ `CF160_1` 形式）。`type` は補足表示
- 設定が無いときの既定は上の6枚（`_DEFAULT_MEDIA_CARDS`）
- 廃棄したカード（`retired: true`）は選択ボタンに出さない。ただし**既に選ばれている記録では表示する**（過去の記録が壊れない）

### 1-3. 旧データ

- 既存の `media` kind（ID `M0001` 形式・10列）は**読むだけ**にする。一覧に「旧記録」として出す。新しく書かない
- bot の CSV 取り込みも、この `media` kind に **ID `L0001` 形式**で保存する（列は既存の10列に収める）:

| bot の列 | 保存先の列 |
|---|---|
| 使用日 | 使用日 |
| 持ち出したメディア | 備考に「持出: …」として残す |
| 使用メディア | 使用カード |
| 現場名 | 現場名 |
| バックアップ（○） | BU確認（○ / 空） |
| 使用者 | 使用者 |
| バックアップした人 | 備考に「BU担当: …」 |
| 返却者 | 返却者 |
| （固定） | メディア種別 = `LINE` ← これが「LINE 取込」の印 |

取り込みは同じ行（使用日＋現場名＋使用者が同じ）を2回入れない。

## 2. ワークシート記入画面（通常）

`#wsd-equip-checklist` の直後・「👤 私物機材」を含む `.wsd-field-group` の**手前**に、新しい `.wsd-field-group` を1つ置く。

```
┌ 💾 メディア                        [選択中 3枚 / 🟡 BU未] ▼ ┐   ← 機材リストと同じ折りたたみバー
│ 📅 使用日      [ 2026/08/17          ] （空なら日程）
│ 📤 持ち出し    [CF160_1][CF160_2][CF160_3][CF160_4][CF256_1][CF256_2]
│ 💾 使用        [CF160_1][CF160_2][CF160_3][CF160_4][CF256_1][CF256_2]  [持ち出しと同じ]
│ 👤 使用者      [川崎][上原]…[松田]   [ または直接入力 ]
│ 💿 バックアップ [ 未 ][ ○ 完了 ]   した人 [川崎][上原]…  [ 直接入力 ]
│ 🔁 返却者      [川崎][上原]…[松田]   [ 直接入力 ]
│ 📝 備考        [                          ]
└─────────────────────────────────────────────────────┘
```

- **折りたたみ**は機材リストと同じ作り（`_setWsdMediaOpen` / `toggleWsdMedia`）。編集部ログイン（`_isEditorLoggedIn`）なら初期状態は畳む。畳んでいてもバーに「選択中 n枚」と「🟡 BU未」「🔴 返却未」を出す
- カードのボタンは `np-select-btn` のトグル（複数選択）。廃棄カードは 1-2 のルール
- 「持ち出しと同じ」は使用欄を持ち出し欄と同じ選択にする
- 名前のボタンは `CREW_NAMES` から生成（単一選択・もう一度押すと解除）＋直接入力。ボタンと入力欄は「どちらか後に触った方」が有効（受付担当と同じ動き）
- 使用者の初期値: `media.user` が空で、担当クルーのカメラマン（`wsd-crew-c`）が入っていればその名前を入れる（保存時ではなく開いたとき。上書きしない）
- バックアップは「未」「○ 完了」の2択トグル。既定は「未」
- 保存は `saveWS()` の中で `data.media = _collectWsdMedia()` を足すだけ。未保存ガード（`_markDirty`）の対象にも入れる
- 作業後記入の「💾 メディア使用記録」（`#wsd-media` textarea）は HTML から**削除**。保存・復元・実データ判定（`_hasRealData` 系）の `'wsd-media'` は読み取り互換のため残してよいが、書き込みは 1-1 のとおり

### 機材リストからメディアを外す

`renderEquipChecklist`（通常WS）と簡易WSのチェックリスト描画で、カテゴリ **`💾 メディア` を出さない**。
例外: そのワークシートで既にチェック済みの品目があるカテゴリは出す（外せなくなるのを防ぐ）。
機材マスタ編集画面・請求コード・`CAT_ORDER` は変えない。

## 3. 簡易ワークシート

同じ欄を「🎥 使用機材」の**下・「📝 備考」の上**に置く（id は `sw-media-*`）。
`saveSimpleWS()` で `rec.media` に保存。折りたたみは無し（簡易は項目が少ないため）。
使用者の初期値は簡易WSの使用者 `sw-user`。使用日が空なら簡易WSの日付。

## 4. 閲覧画面（wsv）と印刷

### 閲覧画面
「📦 レンタル / 私物」の手前に `#wsv-media-section` を足す。`media` に記録があるときだけ表示。

```
💾 メディア
持出: CF160_1, CF160_2, CF160_3
使用: CF160_1, CF160_2, CF160_3
使用者: 城間 ／ BU: ○ 平岡 ／ 返却: 城間          ← BU未なら「🟡 BU未」、返却者空なら「🔴 返却未」
```

### 印刷（通常WS・簡易WS 共通）
「使用機材」の表の直後に **1行だけ**:

```
[メディア] 持ち出し: CF160_1, CF160_2, CF160_3
```

`out` が空なら何も出さない。使用・BU・返却は印刷に出さない（本人決定）。
文字列は `escapeHtml()` を通す。

## 5. 管理室「💾 メディア管理」画面の作り直し

### ヘッダー
`◀ 戻る`　💾 メディア管理／件数　`🔄 更新`　`🎴 カード一覧`　`📥 LINE取込`　`📊 スプレッドシート`（既存リンクは残す）

- 🔄 更新 = `pullKind('order')`・`pullKind('simpleWS')`・`pullKind('media')` を順に。押した瞬間「🔄 取得中…」、終わったら戻す（`_setBtnBusy`）

### 上段：カードの現在地
有効なカード1枚ごとに1タイル。判定は「そのカードが `out` に含まれる記録のうち、使用日が最新（同日なら更新日時が新しい方）」の1件で決める。

| 状態 | 条件 | 表示 |
|---|---|---|
| 🔴 貸出中 | `returnBy` が空 | 使用者・現場名・使用日 |
| 🟡 BU未 | 返却済で、`used` に含まれ、`bu` が偽 | 現場名・使用日 |
| 🟢 返却済 | 上記以外 | 最後の使用日 |
| ⚪ 記録なし | 記録が1件も無い | — |

旧記録（`M`／`L`）は現在地の判定に**使わない**（カードIDが揃っていないため）。

### 下段：記録一覧
- 出どころ3つを1本に並べる（使用日の新しい順）:
  1. 通常WS: `ws_*` のうち削除済みでなく `media` に記録があるもの → タップで `openWSDetail(num)`
  2. 簡易WS: `simple_ws` のうち `media` に記録があるもの → タップで `openEditSimpleWS(id)`
  3. 旧記録: `media_cache` の行（`M`＝アプリ旧、`L`＝LINE）→ タップ不可（閲覧のみ）
- 1行の内容: 使用日 ／ 現場名（件名）／ 出どころの印（`T26051`・`簡易`・`LINE`・`旧`）／ 持出 ／ 使用 ／ 使用者 ／ BU（○ 名前 or 🟡 未）／ 返却（名前 or 🔴 未）
- 絞り込みチップ: `すべて`／`🟡 BU未`／`🔴 返却未`／`LINE`。検索窓は現場名・使用者・カード名・返却者・BU担当を対象（既存の `_normalizeForSearch`）
- 上限500件（既存と同じ）

### 🎴 カード一覧（小さな画面）
- 行: `CF160_1`　`CFexpress Type A 160GB`　`[廃棄／復活]`
- `＋ 追加`（id と種類を聞く。id は英数字と `_` のみ、重複不可）
- **名前変更は付けない**。過去の記録は当時の id で残るので、名前を変えたいときは「廃棄して新しい id を足す」（画面にそう書く）
- 保存は `_saveMediaCards(list)` → `config` kind に push（`orderTypes` と同じ経路・未送信は `pendingAdd`）

### 📥 LINE取込
- ファイル選択（CSV）。bot のシートを「ファイル → ダウンロード → CSV」したもの
- 1行目の見出しで列を探す（順番に依存しない）。見出しの候補: `使用日`／`持ち出したメディア`／`使用メディア`または`使用したメディア`／`現場名`／`バックアップ`／`使用者`／`バックアップした人`／`返却者`
- 1-3 の対応で `media` kind に push。件数と「重複で飛ばした件数」を表示
- 取り込み前に「n件を取り込みます。よろしいですか」の確認

### 廃止するもの
`#new-media-screen`、`openNewMedia`／`closeNewMedia`／`saveNewMedia`、`_nmEditMode` 系、一覧の「＋」ボタン、`_guardedClose` の登録行（`new-media-screen`）。
デスクトップ用 `@media` の `#new-media-screen` ルールも消す。

## 6. 作る順番（それぞれコミット・push・実機確認）

1. カード一覧（データ＋画面）と、ワークシート記入画面のメディア欄（保存・復元・折りたたみ・旧欄の削除と引き継ぎ・機材リストからメディアを外す）
2. 閲覧画面と印刷（通常WS）
3. 簡易ワークシート（記入・保存・印刷）
4. 管理室のメディア管理画面（現在地・一覧・絞り込み・更新）＋単独記録画面の廃止
5. LINE取込（CSV）

各段階で JS 構文チェック・Node テスト・既存テスト（`tests/` 全部）を通す。

## 7. 確認方法

Node（自動・`tests/media/`）:
- `_DEFAULT_MEDIA_CARDS` が6枚で id が bot 形式、`getMediaCards()` が設定なし→既定／設定あり→設定、廃棄が選択ボタンから消え既選択なら残る
- `_collectWsdMedia` ↔ 復元の往復で値が変わらない。旧 `wsd-media` の文が備考へ移り、保存後に `wsd-media` が空になる
- 記録の集計 `_mediaRecords()`: 通常WS・簡易WS・旧記録が1本に並び、削除済みWSが除外され、使用日の新しい順
- 現在地 `_mediaCardStatus()`: 表のとおり4状態になる（同日は更新日時で決着）
- 印刷の1行: `out` があるときだけ、`escapeHtml` を通っている
- CSV 取り込み `_parseMediaCSV()`: 見出しの順番が違っても拾える、重複は飛ばす、`メディア種別` が `LINE`
- 機材チェックリスト: `💾 メディア` が出ない／既チェックがあれば出る
- 構造: 旧 textarea が無い、メディア欄が私物機材より前、`new-media-screen` が無い、関数がトップレベル

実機（本人）:
- スマホ幅／デスクトップ × 文字サイズ100%／150% の4通りでボタンが折り返して収まる
- 編集部ログインでメディア欄が畳まれる
- 保存→別端末で「🔄 更新」→一覧と現在地に出る
- 印刷に「持ち出し」の行だけ出る

## 補足

- 使用日が複数の場合（bot の「複数可」）は、使用日欄に自由に書く（例 `2026/08/17, 08/18`）。集計の並び順は先頭の日付で決める
- 使用者・BU担当・返却者は名前の文字列で持つ（スタッフキーではない）。bot の記録と揃えるため
- 簡易ワークシートは `simpleWS` kind で同期済みなので、他端末でも一覧に出る（コード内の「ローカル保存のみ」というコメントは古い。今回直す）
